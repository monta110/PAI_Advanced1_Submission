# 力覚制御の弱点を発見し、出力調整で改善する

Physical AI 応用1 最終課題向けの第3版です。PyBulletのロボットアームで面を目標8 Nの力で押します。前版で見つかった「硬い接触と力覚遅延で振動する」という弱点に対して、**同じ学習モデルの出力を小さくする対策**を追加しました。

改善だけでなく、慎重に動くために作業時間が延びる代償も示します。全方式を24秒間実行し、元の期限に対応する8秒時点と、24秒時点の両方で評価します。時間を延ばした結果を8秒期限での性能改善として扱いません。

元の基礎版・頑健性評価版は別フォルダに残し、このフォルダが最新の提出用一式です。

## まず確認するもの

- `results_control/demo_control.mp4`：116秒、等速・日本語字幕・音声なしの提出用動画。
- `results_control/説明資料_PAI最終課題_アカウントID.pdf`：目的・方法・結果・限界のレポート。
- `results_control/success_8s.png` と `success_24s.png`：元の制御と対策後を同じ条件・期限で比較。
- `results_control/summary.csv`：27条件×4方式、計108行の集計。

## 今回の実測結果

全27条件をまとめた記述的集計では、元の力覚制御からAI出力1/5へ変えると、24秒時点の成功は578/810から799/810へ増えました。一方、8秒時点は565/810から142/810へ減りました。対策後も11試行は未成功で、全条件を通じた最大力は26.0 N。全条件で安全・高速になる対策ではありません。

評価に約695秒（11.6分）かかりました。環境導入・動画・PDF生成は別です。

## 何を追加したか

| 方式 | 動作 |
|---|---|
| 力覚なし | 同じ学習データ・容量で力入力を0にした回帰モデル |
| 元の力覚制御 | 前版の力覚ありモデルをそのまま使用 |
| AI出力1/5 | 手先zが0.40 m以下になったらモデルの飽和前出力を0.2倍 |
| 1/5＋平滑化 | 同じ出力調整に、力覚入力の指数平滑化（α=0.25）を追加 |

出力に0.2を掛けた**後**で±0.8 mm/stepに制限します。飽和の影響により、実際の移動量が常に元の制御のちょうど1/5になるわけではありません。低い位置に入る前は元の出力を使用し、一度切り替えたら減速状態を維持します。

0.40 mという切替位置は、面高さ235〜265 mmと工具形状から定めた、接触より手前の位置です。**既知の作業範囲という事前知識を使っています。** 各試行の真の面高さや硬さは制御に渡しませんが、任意の作業環境でそのまま使える値ではありません。

平滑化は測定ノイズを抑える一方、追加の応答遅れを生みます。単純な出力調整より常に良いとは限らないため、別方式として比較しています。制御へ入る値は手先zと、遅延・ノイズを含む受信力だけです。

## AIの役割

AIは基礎版と同じ教師ありリッジ回帰です。24種類の面高さで上下探索して得た5,760状態に、単純な力制御教師 `dz=0.00012*(F-8)` m/step のラベルを付けて学習しました。

特徴は `[1, u, u², u³, F/10]`、`u=(z-0.36)/0.04`。力覚なしモデルは力特徴を学習時・推論時とも0にします。他のデータ・容量・正則化は共通です。手先高さには接触の影響が含まれ得ます。

今回の追加部分は**手設計の制御処理**です。AIモデルを再学習・大型化したものではありません。画像・言語・VLA・強化学習は使わず、FlowVLA / ForceVLAの再現でもありません。AI自体が従来制御より優れているという主張はしません。

## 実験条件と公平な比較

- 接触剛性：500 / 2,000 / 8,000 N/m。
- センサーノイズ標準偏差：0.05 / 0.5 / 1.5 N。
- 力覚の追加遅延：0 / 100 / 200 ms（0 / 3 / 6制御周期）。
- 27条件 × 同じ30通りの面高さ × 4方式 = **3,240試行**。
- 物理240 Hz、制御30 Hz。全方式を24秒実行。
- 面高さ235〜265 mmの一様分布。評価高さseed=90401、ノイズseed=25000+試行番号。
- 予備試験には別の固定高さ（.238/.250/.262 m）とseedを使い、最終評価とは分離。
- 同じ試行番号では、すべての方式・条件で同じ高さと標準正規乱数列を使用。真の力の軌跡は制御の違いで変わります。

剛性はPyBulletの `contactStiffness` を工具・対象の双方に設定した値です。物体ペアの有効剛性や材料硬度の実測値ではありません。減衰は双方30で固定。力は工具と対象の接触反力を8物理ステップで平均し、ノイズを加え、0未満を0に丸めてから遅延させます。未受信の履歴は0。追加遅延0でも、前周期の力を参照する通常のサンプル値制御です。

## 指標

すべて、遅延・ノイズを加える前の真の接触力で計算します。

- **8秒時点の成功**：6〜8秒相当の末尾60サンプルの90%以上が8±1 N内で、最初の8秒間の最大接触力が16 N以下。
- **24秒時点の成功**：22〜24秒相当の末尾60サンプルの90%以上が8±1 N内で、最初の24秒間の最大接触力が16 N以下。
- **MAE / RMSE**：評価時点直前2秒の目標からの誤差。
- **最大力**：物理ステップ単位の全区間最大。制御周期平均より大きい場合があります。
- **押し過ぎ量**：`max(0, 最大力-8 N)`。
- **安定時刻**：8±1 Nに入り、終了まで維持し、最低1秒分のサンプルが残る最初の時刻。開始から測定。
- **未安定**：`null` / CSV空欄。0秒に置き換えず、安定数と安定した試行だけの平均を併記。

成功と安定は別です。最後は安定しても途中で16 Nを超えると成功になりません。16 Nはこの実験の便宜的なしきい値であり、安全保証ではありません。

## ZIPの使い分け

提出用ZIPにはコード・モデル・動画・PDF・集計表を入れています。大きな全時系列ファイルは別の実験記録ZIPです。既存の結果を全時系列から検査したい場合は、両ZIPを同じ場所に展開して `force_touch_control/results_control/` にNPZが入るようにしてください。提出用ZIPだけでも、実験を再実行すれば全時系列が生成されます。

## 再実行

Python 3.12、macOS Apple Silicon、CPUで検証。GPU・APIキー・ROS・実機は不要です。既存の動画とPDFを見るだけなら再実行は不要です。

Mac/Linuxではこのフォルダで `sh run.sh` を実行します。環境作成、評価、検証、動画、PDFを一括で生成します。MacでのPyBulletビルドにはXcode Command Line Toolsが必要です。標準ヘッダの読み込み順によるエラー回避として `CFLAGS='-include stdio.h'` を設定しています。Windowsは未検証です。

既存環境の場合：

```sh
python -m pip install -r requirements.txt
python upgrade.py
python verify_control.py
python make_control_video.py
python make_control_report.py
```

- 学習済みモデルを固定して使用します。学習から再現したい場合のみ、先に `python experiment.py` を実行してください。モデル変更後は全評価・動画・PDFを作り直します。
- 短い動作確認：`python upgrade.py --trials 2 --out /tmp/force_touch_control_smoke`。
- 境界検査のみ：`python verify_control.py --unit-only`。
- Linuxなどで日本語フォントを検出できない場合は、`DEMO_FONT` にNoto Sans CJK等のフォントファイルを指定してください。
- 再実行は `results_control/` の同名ファイルを上書きします。

- `protocol.json`：評価前に保存した条件、seed、モデルと実験コードのSHA-256。
- `trials.csv`：全3,240試行の指標。`summary.csv/json`：条件別108行。
- `traces_k500.npz` / `traces_k2000.npz` / `traces_k8000.npz`：全時系列を硬さ別に分割。解析しやすいよう硬さ別に保存しています。提出用ZIPには含めず、別の実験記録ZIPにまとめています。
- 列：時刻、制御前手先z、真の平均力、物理ステップ最大力、飽和前モデル出力、最終指令、受信力、遅延前センサー値、制御後目標z、特徴量化直前の力値、倍率、減速状態。力覚なし方式では、この力値が特徴量化時に0へマスクされます。
- `validation.txt`：減速切替と倍率、状態維持、指数平滑化、入力マスク、元の8秒軌跡との一致、全時系列の8秒/24秒再集計、遅延、ソースとモデルのハッシュ、ストレス条件の再実行を検証。

## 説明するときの要点

- **AIは何をしているか**：教師の制御出力を学習した回帰モデルが、手先を上下に動かす量を出します。今回も学習済み係数は同じです。
- **なぜ遅延で振動するか**：過去の低い力を見て押し続けると、実際には力が増えていても追加の動作をしてしまいます。
- **改善した部分は何か**：接触に近づいたらモデル出力を0.2倍にする、手設計の処理です。AI自体を高度化したわけではありません。
- **24秒に延ばすのは公平か**：元の方式も新方式も同じ24秒動かし、元の8秒期限での成績も併記します。期限が8秒なら、新方式でも失敗する場合があります。
- **何が未検証か**：実機、画像や言語の入力、未知の作業範囲、材料の実測モデルです。切替位置も環境に依存します。
